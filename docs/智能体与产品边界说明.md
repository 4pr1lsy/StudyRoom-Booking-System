# 智能体与网页产品边界说明

## 1. 两个不同层次

本项目同时包含软件产品开发和软件项目管理实验中的角色化协作，但二者不是同一个交付物：

- **软件产品**：自习室预约网页，采用 HTML、CSS、JavaScript 和浏览器 localStorage 实现。
- **项目管理实验协作**：通过大模型对话，按不同项目职能扮演角色，协作完成范围、进度、成本、质量和变更管理，并保留提示词、输入、输出、审核和事件记录。

## 2. 六类 Agent 的定位

本项目采用六类项目管理与开发过程角色：

| Agent | 模拟职能 | 主要工作 |
|---|---|---|
| PM Agent | 项目经理 | 项目统筹、状态汇总、协调与管理建议 |
| Architect Agent | 系统架构师 | 技术路线、模块边界和数据结构设计 |
| Planner Agent | 项目计划人员 | WBS、工期、依赖、关键路径和进度分析 |
| Developer Agent | 开发人员 | 根据确认的需求生成、解释或修改代码 |
| QA Agent | 测试人员 | 测试设计、缺陷分析、验收与回归建议 |
| Change Control Agent | 变更控制职能 | 变更申请分析及范围、进度、成本、质量影响评估 |

学生是预约网页的使用者，也是项目中的外部用户干系人；可以通过需求场景或反馈提出需求，但不单独设置 Student Agent。

## 3. 技术与证据边界

六类 Agent 通过角色提示词和大模型对话/协作方式参与课程实验，不是预约网页中的六个机器人，也不要求预约网页启动时调用 DSAPI、AgentAPI 或其他大模型接口。

每项角色化协作应尽量保留角色、输入、输出、采用的提示词、人工审核和事件记录。历史对话可以回溯整理，但应标明为历史工作记录；不得将未发生的 API 调用、并行独立 Agent 服务或未执行的测试写成已完成事实。

## 4. 软件产品边界

V0.2 网页核心版只实现自习室展示、座位状态、日期与时间选择、创建预约、冲突检查、查看预约和取消预约、本地持久化。CR-001“预约时间修改”仍为候选变更，未获正式批准前不纳入当前产品版本。
